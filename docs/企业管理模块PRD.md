# 企业管理模块 PRD

## 1. 模块概述

企业管理模块用于后台管理员创建、编辑和查看企业客户信息。每个企业拥有独立的登录凭证、溢价系数和月账期额度。

### 核心能力
- 企业账号的 CRUD 管理
- 自动生成唯一企业 ID
- 地区号与国家/币种联动
- 完整的字段校验体系
- 密码脱敏显示

---

## 2. 数据模型

| 字段 | 类型 | 说明 | 规则 |
|------|------|------|------|
| id | string | 企业ID | 格式：`ENT-YYYYMMDD-XXX`，系统自动生成，不可修改 |
| name | string | 企业名称 | 2-50字符，禁止 `< > ' " & \`，全局唯一 |
| countryCode | string | 地区号 | 下拉选择：+852/+66/+86/+65/+60 |
| phone | string | 登录手机号 | 纯数字，位数由地区号决定，同地区唯一 |
| password | string | 登录密码 | 8-20位，须同时包含字母和数字 |
| country | string | 国家 | 由地区号自动确定 |
| currency | string | 币种 | 由地区号自动确定 |
| premiumRate | number | 溢价系数 | 范围 1.00-3.00，精度 2 位小数 |
| creditLimit | number | 月账期额度 | 整数，0-10,000,000 |
| usedCredit | number | 已用额度 | 系统计算，不可手动修改 |
| createdAt | string | 创建时间 | 系统自动生成 |

## 4. 页面交互说明

### 4.1 企业列表页 `/admin/enterprises`

**列定义（从左到右）**：
1. 企业ID — `font-mono` 等宽字体
2. 企业名称
3. 登录手机号 — 显示格式：`{地区号} {号码}`
4. 登录密码 — 默认显示 `••••••••`，点击眼睛图标切换明文/脱敏
5. 国家
6. 溢价系数
7. 月账期额度 — 显示格式：`{币种} {金额}`
8. 已用额度
9. 创建时间
10. 操作 — 更改信息 / 交易明细 / 订单记录

**搜索**：支持按企业ID、名称、手机号搜索。

### 4.2 创建企业页 `/admin/enterprises/create`

**交互流程**：
1. 填写表单（所有字段均有校验）
2. 选择地区号 → 自动锁定币种、调整手机号校验
3. 点击「创建账号」→ 校验通过后弹出 Modal 展示生成的企业ID
4. 点击「返回列表」回到列表页

**表单字段**：企业名称、登录手机号（地区号+号码）、登录密码（`Input.Password`）、溢价系数、月账期额度（币种+金额）

### 4.3 编辑企业页 `/admin/enterprises/[id]/edit`

与创建页对称，差异点：
- 表单顶部展示企业ID（`disabled Input`，不可修改）
- 唯一性校验（企业名称、手机号）排除当前企业自身
- 预填充现有数据

---

## 5. 校验规则详细说明

### 企业名称
- 必填
- 长度：2-50 个字符
- 禁止字符：`< > ' " & \`
- 全局唯一（编辑时排除自身）

### 登录手机号
- 必填
- 只允许数字
- 位数根据地区号动态校验（见映射表）
- 同地区号下唯一（编辑时排除自身）
- 切换地区号时自动重新校验

### 登录密码
- 必填
- 长度：8-20 个字符
- 必须同时包含字母和数字
- 创建/编辑页使用 `Input.Password` 组件（支持显示/隐藏）
- 列表页默认脱敏显示

### 溢价系数
- 必填
- 类型：数字
- 范围：1.00 ~ 3.00
- 精度：2 位小数

### 月账期额度
- 必填
- 类型：整数
- 范围：0 ~ 10,000,000
- 币种由地区号自动确定，不可手动选择

---

## 6. 企业 ID 生成规则

格式：`ENT-YYYYMMDD-XXX`

- `ENT`：固定前缀
- `YYYYMMDD`：创建日期
- `XXX`：三位序号，同日内自增（001, 002, ...）

示例：`ENT-20260330-001`

## 7. 子母账号管理（子账号 Sub-account）

> 本节记录的是运营后台"子母账号"能力的当前设计，此前版本的 PRD 未涵盖该能力。子账号在客户端（企业自己的用户）侧已有对称实现，见 `src/components/EnterpriseManagementPanel.tsx`（客户端"母账号设置 > 子账户设置"面板）。

### 7.1 设计原则

- **列表页 / 创建流程不涉及子账号**：`/admin/enterprises` 列表只展示企业（母）账号，不再混排子账号行；「创建企业账号」页只能创建企业账号，不再提供"选择账号类型"（企业账号 / 子账号）的入口。
- **子账号管理入口收敛到企业详情页**：运营人员进入某个企业的「详情」页（`/admin/enterprises/[id]`），在「订单记录」「交易明细」之后新增「子账号管理」Tab，子账号的新增、编辑、启停均在这个 Tab 内完成。
- **子账号额度没有独立的池子**：子账号的"已分配额度"直接从所属企业自身的「每月账期额度」（`creditLimit`）中划分，不需要运营额外填写一个"总额度上限"。可分配额度 = `creditLimit - 已分配子账号额度合计`。
- **"开通子账号功能"无需单独的关闭入口**：子账号列表里每一行本身就有独立的启停开关（状态列），要"关闭"某个子账号直接停用即可；不提供整体撤销"母账号资格"的入口。
- **子账号的能力完全依附于所属企业**：企业（母账号）本身被停用时，其下所有子账号视为一并不可用（无法登录/下单），这个状态由企业自身的启停状态决定，不需要（也不会）反过来修改每个子账号自己的 `status` 字段。
- **列表页暂不展示子账号数量**：曾评估过在 `/admin/enterprises` 列表加一列"子账号数"角标，用户反馈暂不需要，已还原为不展示；运营需要点进企业详情的「子账号管理」Tab 查看。

### 7.2 数据模型（`src/data/adminMockData.ts`）

```ts
interface Enterprise {
  // ...原有字段
  isParent?: boolean;              // 是否已开通子账号功能
  subAccounts?: AdminSubAccount[]; // 该企业下的子账号
}

interface AdminSubAccount {
  id: string;
  name: string;
  phone: string;
  quota: number;    // 已分配额度（CNY，从企业 creditLimit 中划分）
  balance: number;  // 当前余额（CNY）
  status: 'active' | 'disabled';
  createdAt: string;
}
```

### 7.3 企业详情页「子账号管理」Tab 交互

- **未开通（`isParent` 为空/false）**：展示空状态提示"该企业尚未开通子账号功能" + 「开通子账号功能」按钮。点击后二次确认（无需填写金额，因为额度池就是企业自身的 `creditLimit`），确认后 `isParent` 置为 `true`，可以开始新增子账号。
- **已开通**：
  - 子账号列表表格：账号名称 / 手机号 / 已分配额度 / 本月当前余额 / 状态（启停开关）/ 操作（编辑）。
  - 「新增子账号」：弹窗表单（账号名称、手机号+区号、登录密码、分配额度），分配额度校验不能超过当前剩余可分配额度；剩余额度 ≤ 0 时按钮禁用。账号名称额外校验：不能与所属企业名称相同（如"菜鸟物流国际"下的子账号不能叫"菜鸟物流国际"）；同一企业下子账号名称必须互不相同。
  - 「编辑子账号」：可修改账号名称、手机号、分配额度（校验同上，排除自身后重新计算剩余额度）、通过「修改密码」入口单独修改登录密码。账号名称校验与新增一致（不能与企业名称相同、不能与同企业下其他子账号重名，排除自身）。
  - 账号名称的这两条校验（不能与企业名称相同、同企业内子账号名称唯一）在客户端 `EnterpriseManagementPanel.tsx` 的新增/编辑弹窗里同步实现，保持两端行为一致。
  - 启停：停用需二次确认，停用后该子账号无法登录，历史订单仍可查看。
  - 「额度分配情况」卡片：企业账期总额度 / 已分配子账号 / 未分配（企业可用），若企业账期额度被运营调低导致子账号分配总和超额，展示警示提示。
- 新增的子账号会实时反映在同一详情页的「订单记录」「交易明细」Tab 的"全部账号"筛选下拉框中。
- **企业账号（母账号）已停用时**：Tab 顶部展示警示提示"企业账号已停用，其下所有子账号均无法登录下单"，仅作提醒，不限制运营在 Tab 内继续新增/编辑/启停子账号——保持逻辑简单，运营的管理操作不因企业停用而被锁定。
- **演示状态按钮**：与客户端 `EnterpriseManagementPanel` 一致，Tab 底部提供「演示空状态」「演示超额分配」两个 dashed 按钮，用于快速切换展示空列表/超额分配警示；另外新增「演示企业停用状态」按钮（未开通和已开通两种视图下都有），用于在不真正修改企业启停状态的前提下预览企业停用后顶部警示条的展示效果。这三个按钮仅影响本 Tab 的本地展示状态，不写入 `enterprise` 数据。

### 7.4 已知限制（Demo 范围内）

- **无持久化，且改动不跨页面同步**：子账号的新增/编辑/开通只写入企业详情页的本地 React state，不会回写 `adminMockData.ts` 的模块级 `enterprises` 数组。这与本后台其余"创建/编辑"页面的既有行为一致（如「创建企业账号」「编辑企业账号」提交后同样只弹出成功提示、不真正持久化），不是本次新增的问题，但影响范围更明显：
  - 刷新详情页，或离开后重新进入，子账号的改动会重置为 mock 初始数据。
  - 同一会话内，`/admin/orders`、`/admin/transactions` 页面各自独立从模块级 `enterprises` 读取子账号名单，看不到刚在「子账号管理」Tab 里做的新增/改名/改额度。
  - 「更改资料」编辑页里"账期额度低于子账号已分配额度合计"的预警，同样读的是模块级 `enterprises`，看不到刚在 Tab 里做的额度变更。
  - 如果需要跨页面/跨刷新保持一致，需要把 `enterprises` 提升为应用级共享 state（或接入真实后端），属于比本次改动更大的架构调整。
- 目前 mock 数据中只有 `E001`（菜鸟物流国际）预置为已开通（`isParent: true`）状态，其余企业默认未开通，需要运营手动开通后才能新增子账号。
- 停用子账号时不检查该子账号是否有在途订单（客户端 `EnterpriseManagementPanel` 原逻辑同样如此，非本次改动引入）。
